Here’s how I would solve it, given the three input/output pairs.

1) Infer the task from the examples
- Each input has a sparse set of non-zero cells, all using a single color (8 in the first, 1 in the second, 2 in the third).
- Each output uses 5 as the background and “completes” a global geometric pattern entirely with that dominant non-zero color.
- The completed pattern is a family of axis-aligned, concentric square “rings” (drawing only the borders), expanding outward from an anchor on the top row or the left column. The gaps between rings follow a fixed stride: either 2 or 3 cells.
- The non-zero cells in the input are samples of that ring pattern. The job is to (a) infer the anchor location and stride from those samples and (b) render all rings across the whole grid with that color, leaving everything else as 5.

2) Extract the dominant color and its “clue” cells
- Compute the most frequent non-zero value in the input; call it c. This will be the color we use to draw the rings.
- Collect all coordinates where the input equals c. These are the “primary cells,” i.e., samples of the target ring structure.

3) Hypothesis for the ring generator
- Assume there’s an anchor point (r0, c0) located either on the left edge (any row, column 0) or on the top edge (row 0, any column).
- Assume a stride s ∈ {2, 3}. The ring index i runs from 0 outward. The i-th ring has borders defined by:
  - left  = c0 − s*i + (s − 1)
  - right = c0 + s*i − 1
  - top   = r0 − s*i + (s − 1)
  - bottom= r0 + s*i − 1
- The border cells of ring i are those with:
  - column in {left, right} and row between top and bottom (inclusive), or
  - row in {top, bottom} and column between left and right (inclusive).
- This particular asymmetric offset ((s − 1) on the “minus” side and −1 on the “plus” side) is what aligns the parity and phase of the rings so they match the examples. It’s the key to getting the ring positions to line up with the clues.

4) Validate a candidate anchor and stride
- For each candidate stride s in [2, 3]:
  - First, try all possible anchors on the left edge: (r, 0) for all rows r.
    - For this (r0, c0, s), check if every primary cell lies on the border of some ring i generated by the formulas above. Increase i from 0 upward until the ring rectangle is completely outside the grid (at which point you stop). If each primary cell is hit by some ring border, the candidate is valid.
  - If none works, try all possible anchors on the top edge: (0, c) for all columns c), with the same validation.
  - Use the first valid (r0, c0, s) you find. If none is found at all, fall back to a default like (0, 0, 2).

5) Render the output
- Initialize the output as a grid fully filled with 5.
- Using the found (r0, c0, s), generate rings for i = 0, 1, 2, … using the bounds above. For each ring:
  - Draw the left and right borders where they intersect the grid.
  - Draw the top and bottom borders where they intersect the grid.
  - Assign color c to those border cells.
  - Stop when the entire ring rectangle is beyond the grid both horizontally and vertically.
- Return the filled grid.

6) Why this matches the examples
- The dominant non-zero color is preserved and extended to a complete ring pattern across the grid.
- The anchor on the top row or left column, together with the stride 2 or 3 and the asymmetric offset, reproduces the exact phasing/parity seen in the outputs.
- Anything not on a ring border remains 5, matching the backgrounds in all outputs.

This approach turns the sparse clues into a parameter-identification problem (anchor and stride), then uses those parameters to synthesize the complete geometric pattern deterministically.
