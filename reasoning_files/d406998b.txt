Here’s how I’d solve it:

1) Spot the invariants
- Zeros never change.
- Only 5s sometimes become 3s.
- The set of 5s that change follows a consistent column pattern across every row in a sample.

2) Identify the column pattern
- Example 1 (width = 10): 5s change at column indices 1, 3, 5, 7, 9 (0-based odd).
- Example 2 (width = 12): again, changes happen at odd indices.
- Example 3 (width = 13): 5s change at even indices.
- Example 4 (width = 14): 5s change at odd indices.
- So the “odd/even” condition depends on the width parity. That suggests the rule is tied to distance from the right edge rather than from the left.

3) Reframe using right-to-left indexing
- Let N be the number of columns.
- For a cell at left-based index j, define its right-based index as N - 1 - j (i.e., 0 at the rightmost column, 1 next to it, etc.).
- Checking the examples:
  - When N is even (10, 12, 14), 5s change when j is odd. That means right-based index is even.
  - When N is odd (13), 5s change when j is even. That also means right-based index is even.
- Therefore, the unified rule: change a 5 to 3 if its right-based index is even.

4) Apply the rule per element
- For each cell:
  - If value == 5 and (N - 1 - j) % 2 == 0, output 3; otherwise, keep the original value.

5) Apply per row and per grid
- Transform each row by applying the element rule to all columns.
- The samples always have 3 rows, so process the first 3 rows of the grid.

6) Complexity and correctness
- This is a simple O(rows × cols) pass.
- The rule matches all given examples:
  - Width 10 and 12: changes at left-odd columns.
  - Width 13: changes at left-even columns.
  - Width 14: changes at left-odd columns.
- Only 5s are changed; zeros (and any non-5s) stay as-is.
