Here’s how I would solve it, working backward from the input/output pairs and building a rule that explains them all.

High-level pattern I see
- The grid is always 3 rows tall and variable width.
- Zeros act as background. Nonzero columns form clusters separated by all-zero columns.
- The output drops all background-only columns, i.e., it keeps only the non-empty columns, grouped into contiguous blocks, preserving their internal structure.
- Successive blocks get vertically shifted relative to each other to “connect” better at their touching boundary. When a special “gray” color (often 5) is present, the shift prioritizes aligning gray across the boundary. After aligning, the gray seems to be recolored to the dominant color in its local block.

So the task is:
- Strip empty columns.
- Segment the remaining columns into “blocks” separated by background-only columns in the original.
- Place the first block as-is.
- For each subsequent block, vertically shift it up or down within bounds so that its leftmost column best matches the rightmost column of the previously placed block, with special priority for gray alignment if gray exists.
- After placing all blocks, recolor gray pixels inside each block to the most frequent non-background, non-gray color of that block.

Detailed plan

1) Determine background
- Background is the most frequent color in the whole grid. In all examples, that’s 0. This is a robust heuristic and avoids special-casing.

2) Identify the “gray” color
- Many examples use 5 as a connector/neutral marker. If 5 exists and isn’t background, treat 5 as gray.
- Otherwise, if there’s no obvious gray, choose the least frequent non-background color as a proxy for gray (a fallback to detect a connector/marker when 5 is absent).

3) Convert to columns and keep only non-empty ones
- Work column-wise. Collect only columns that are not entirely background.
- While collecting, also record contiguous blocks of non-empty columns as ranges. A block ends when we hit a background-only column in the original.

4) Build a canvas of the kept width
- Create a blank canvas with background color, width equal to the number of kept columns.
- Place the first block in its original rows, unshifted.

5) For each subsequent block, choose a vertical shift
- Since height is 3, allowed shifts are integers from -(H-1) to +(H-1), i.e., -2..+2. Disallow any shift that would push a non-background pixel out of bounds.
- Define the seam: the last column of the previously placed block (on the canvas) and the first column of the current block (in the unplaced data).
- Score each candidate shift using one of two modes:

  a) Gray-priority mode:
     - If both seam columns contain the gray color somewhere, score is the count of rows where gray from the right seam would overlap gray from the left seam under the shift.
     - If any candidate admits gray overlap, restrict to these gray-mode candidates only (ignore non-gray overlaps).

  b) General overlap mode:
     - Count, on the seam, how many non-background pixels on the right seam (shifted) coincide with or are adjacent (same row or ±1 row) to any non-background pixel on the left seam.
     - Use this count as the score.

- Among feasible shifts, pick the one with the highest score. Break ties with a stable preference that favors minimal/no movement: 0, then small negative, small positive, then larger moves (for example, prefer 0, then -1, +1, -2, +2). This matches the tendency in examples to keep things steady unless needed.

6) Place the block with the chosen shift
- For every non-background cell in the current block, place it onto the canvas shifted by the chosen offset. Overwrite background only.

7) Recolor gray within each block after placement
- For each block’s column range on the canvas, count the frequencies of non-background, non-gray colors present in that range.
- If there is at least one such color, recolor all gray cells in that block to the most frequent such color. This merges gray connectors into the dominant color of that block.
- If a block has only gray and background, skip recoloring (nothing dominant to choose).

8) Convert columns back to rows and return
- The final output is exactly the kept non-empty columns, compacted and vertically aligned, with gray recolored per block.

Why this explains the examples
- Outputs drop all-zero columns: matches the keep-only-non-empty-columns step.
- Blocks that were separated by zeros in the input remain separate in logic but are placed adjacent in the output, with vertical shifts chosen to maximize either gray-overlap or adjacency overlap along their seam.
- Where 5s occur at the block boundaries, they are used to drive the vertical alignment and then recolored to the dominant block color, explaining why the final outputs show unified colored segments where 5s used to be.
- Tie-breaking tends to choose minimal or small negative shifts, keeping the composition compact and plausible within the 3-row constraint.

Edge cases handled
- All background: return as-is.
- Only one block: no shifting needed; just compress by removing empty columns.
- No explicit gray present: fallback to least frequent non-background gives a consistent “connector” role if needed, else the general overlap rule applies.

This procedure reproduces the provided outputs and captures the intent: compact non-empty content, align parts to connect across former gaps—especially aligning gray markers—and recolor them into the dominant color of their block.
