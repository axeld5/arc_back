Here’s how I would solve it, given the I/O pairs:

- First, notice the outputs are not the entire minimal bounding box around the positive numbers, but rather a 3x3 tile that corresponds to the top-left quadrant of that bounding box. In both examples, the nonzero region spans a 6x6 area; the output is the top-left 3x3.

- Approach:
  1. Scan the grid and collect all coordinates whose values are > 0.
  2. From those coordinates, compute the minimal and maximal column index (min_col, max_col) and the minimal and maximal row index (min_row, max_row). This gives the bounding box of the nonzero region.
  3. To keep only the top-left quadrant of that bounding box, shrink the right and bottom edges inward by half the span:
     - Let span_col = max_col - min_col and span_row = max_row - min_row.
     - Define new_max_col = max_col - (span_col // 2) and new_max_row = max_row - (span_row // 2).
     - This effectively takes the left half (in columns) and the top half (in rows) of the bounding box. Using integer division ensures clean halving for both even and odd spans.
  4. Slice the original grid using rows [min_row : new_max_row] and columns [min_col : new_max_col]. With exclusive-end slicing, this produces exactly the desired top-left quadrant.

- Why this matches the examples:
  - In the first grid, the nonzero region spans rows 2..7 and cols 2..7 (inclusive), which is 6x6. Halving yields rows 2..4 and cols 2..4 (3x3), matching the output.
  - In the second grid, the nonzero region spans rows 1..6 and cols 1..6; halving similarly yields rows 1..3 and cols 1..3.

- Summary:
  - Extract positive-value coordinates.
  - Compute their bounding box.
  - Replace the bottom/right bounds with the midpoint (max - half the span).
  - Slice the grid with start at the mins and end at these midpoints (exclusive).
  - Return that cropped subgrid.
