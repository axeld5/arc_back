Here’s how I would solve it from the given input/output pairs:

1) High-level pattern from the IO
- The numbers 2 and 4 form the “skeleton” of a multi-colored shape.
- In at least one place on the grid, that skeleton comes with “decorations” 1 and 3 at specific relative offsets inside the same connected shape that contains 1, 2, 3, and 4 together.
- Elsewhere on the grid, the same skeleton (2s and 4s) appears again, possibly rotated or mirrored, but the 1s and 3s are missing.
- The task is to copy the 1/3 pattern from the reference occurrence and stamp it onto every other instance of the 2/4 skeleton, under any rotation and horizontal flip, without overwriting 2s or 4s.

2) Identify the reference pattern
- Scan the grid to find connected components using 8-neighborhood (diagonals count as connected in the shapes).
- For each component, collect the set of colors present.
- The first component that contains all of {1, 2, 3, 4} is the reference. This is the only place that tells us how 1 and 3 sit relative to the 2/4 skeleton.

3) Normalize the reference component
- Record all coordinates in that component, and compute its top-left (min row, min col).
- Convert each cell’s absolute coordinates to offsets relative to that top-left.
- Separate these offsets by color:
  - Blue = positions with 1
  - Red = positions with 2
  - Green = positions with 3
  - Yellow = positions with 4
- The anchor mask will be the union of Red and Yellow. The payload to copy will be Blue and Green.

4) Define the pattern’s bounding box for matching
- Compute the bounding box height/width using only the Red+Yellow offsets. This is the skeleton window you will slide across the grid.
- The reason: we want to match only the skeleton (2s and 4s) in the target areas; 1/3 shouldn’t constrain the match and may be absent initially.

5) Handle symmetries of the pattern
- Consider all 8 symmetries of the pattern: 4 rotations (0, 90, 180, 270 degrees) and an optional horizontal flip.
- Implement transformations that:
  - Optionally flip horizontally (mirror columns within the bounding box).
  - Rotate k times (updating both coordinates and the bounding box dimensions).
- Apply the same transform to the Red, Yellow, Blue, and Green offsets.

6) Search for matches of the skeleton
- For each transformed skeleton (Red/Yellow offsets) and its transformed payload (Blue/Green):
  - Slide the skeleton window over the entire grid wherever it fits within bounds.
  - A position (r, c) matches if:
    - Every Red offset corresponds to a 2 in the grid at (r+dr, c+dc).
    - Every Yellow offset corresponds to a 4 in the grid at (r+dr, c+dc).
    - None of the Blue/Green offsets would land on a 2 or 4 (to avoid overwriting skeleton cells).
- If a match is found, paint the payload:
  - Set the Blue offsets to 1.
  - Set the Green offsets to 3.
- Keep checking all placements and all symmetries; apply to all matches.

7) Practical details
- Work on a copy of the input grid to produce the output.
- Use the original (pre-modification) grid for matching the skeleton so that one placement doesn’t affect the detection of another.
- If no component contains all four colors {1, 2, 3, 4}, return the grid unchanged.

Why this matches the IO examples:
- In each example, there is one “complete” occurrence with 1/2/3/4. Elsewhere, the same 2/4 skeleton appears rotated or mirrored but lacks 1/3. The algorithm finds that reference, records 1 and 3 relative to the 2/4 skeleton, searches the grid for any symmetry of that skeleton, and stamps 1s and 3s accordingly, preserving 2s and 4s. This produces exactly the added 1s/3s seen in the outputs.
