2) Algorithm design
- Traverse the grid cell-by-cell. When you find a non-zero cell that hasn’t been handled, flood-fill its entire connected component of that label using a stack/DFS (4-directional adjacency).
- For each component:
  - Compute min_row and max_row among its cells; the component height is H = max_row − min_row + 1.
  - For every (row, col) in the component, place its value at (row − H, col) in a new, zero-filled grid.
- Keep a “processed” set to avoid revisiting cells in already-extracted components.
- Return the new grid.

3) Implementation details I’d follow
- Flood-fill: maintain a stack, a visited set local to the component, and expand only to neighbors with the same label and inside bounds.
- New grid: initialize with zeros; write only the lifted component cells into it.
- Iterate the original grid in row-major order; after extracting a component, mark all its cells as processed so they aren’t reprocessed.
- Assumptions consistent with the data:
  - Lifting by H doesn’t push cells above row 0 (the examples satisfy this).
  - Lifted components don’t overlap in the target grid (the examples satisfy this).
- Complexity: O(N) over cells, since each cell is visited a constant number of times.

4) Function structure I’d use
- A helper to find a connected component of a given label starting from a seed (stack-based DFS).
- A helper to compute the component’s height and write it lifted into the new grid.
- A main solve that loops cells, extracts components, and assembles the output grid.
- A thin wrapper p that calls solve.
